## Slide 12 · Workflow vs Agent 스펙트럼 (1'45")

**발화 포인트**
- Augmented LLM → Workflow → Agent
- Anthropic 권고 — **"단순함에서 시작, 필요할 때만 자율성 ↑"**
- Workflow가 적합 — 작업 명확·예측 가능성 가치·비용 통제 우선

# 부록 A · Q&A 대비 예상 질문 + 답변

## A1. "에이전트 도입 ROI는 어떻게 측정하나요?"

- 즉답 — Trace 1건 = 비용 1건. EBIT 영향 측정은 BCG 2026-01 5%만 도달.
- 측정 단위 — 작업 1건당 인시 절감 / 시간 절감 / 품질 (Eval 통과율)
- 비교 — SK플래닛 -41.7% 시간 / Nubank 인시 12배 / 보안 픽스 20배
- 함정 — 도입률만 추적하면 "94% 투자 vs 5% 가치" 함정 (BCG)

## A2. "LangGraph vs LangChain vs CrewAI vs AutoGen 어느 것을 써야 하나요?"

- 본 강의는 프레임워크 선택을 다루지 않음 — 가이드 부록 참조
- 짧은 답 — LangChain은 빌딩 블록, LangGraph는 실행 엔진. 다단계 + 재시작 + 사람 승인 + 감사 로그 필요 시 LangGraph.
- 2026 — LangGraph v0.4 · AutoGen 1.0 GA · CrewAI Enterprise (옵저버빌리티 + 스케줄링) — 프레임워크 성숙기.
- 선택 기준 — 팀 익숙도 · 토폴로지 (Single → LangGraph, Multi 협업 → CrewAI) · 엔터프라이즈 옵저버빌리티 요구.

## A3. "MCP를 도입하면 보안 위험은?"

- MCP 자체는 표준 — 보안은 구현·운영의 문제.
- 위험 — Server 자체에 권한 부여 (예: GitHub MCP가 repo 전부 접근), 인증 토큰 관리, Tool description 인젝션
- 대응 — Anthropic Managed Agents (2026-05) — MCP Tunnels (사내망 안전 노출) · Self-hosted Sandboxes (사용자 인프라 격리)
- 한국 사례 — 네·카·당 OpenClaw 금지령 (2026-02) = 권한 격리 부재 우려

## A4. "Korea AI 기본법 — 우리 회사도 영향평가 해야 하나요?"

- 영향평가는 노력 의무 (강행 아님). 단 고영향 영역 (채용·대출·의료·교통·법집행 등)이면 사실상 필요.
- 일반 SaaS·내부 도구는 직접 적용은 아니나 사용자 보호 가이드 (개인정보위 2026-05-19) 권고 사항.
- EU 진출 계획 있으면 EU AI Act 기준 (사실상 글로벌)
- 산출물 — 영향평가 보고서 · 위험등급표 · 완화조치 (ISO 42001 인증 시 자연스럽게 충족)

## A5. "Multi-Agent 보다 단일 Agent + 도구 풍부가 낫다는 이유는?"

- Anthropic의 권고 — 복잡도와 비용이 비선형 증가
- 단일 우위 — 디버깅 용이 · 책임 명확 · trace 단순 · 비용 예측 가능
- Multi 가야 할 때 — 도메인 분리 명확 (다른 부서·다른 SLA) · 책임 경계 분명 · 역할별 모델 크기 분리 필요
- 함정 — N제곱 비용 · Trace 경계 횡단 · Hop Count 무한
- 사례 — Devin은 단일 (장시간 실행) · CrewAI Multi-Agent Supervisor 패턴

## A6. "Reasoning model 1급화 — 비용은 어떻게 통제하나요?"

- 2026 — Adaptive Thinking · thinkingLevel · o-series 모두 **요청 복잡도에 따라 자동 조절**
- 직접 통제 — Anthropic은 thinking budget 파라미터 · Google은 thinkingLevel
- 라우팅 정책 — 단순 작업은 reasoning OFF, 고난도만 ON
- 측정 — Trace에 thinking token 별도 기록 (OpenTelemetry GenAI conventions)

## A7. "한국 청중인데 한국 사례 더 많이 알고 싶습니다."

- 본 강의 인용 — SK플래닛 / 우아한형제들 물어보새 / 삼성전자 DX / SKT / 카카오 / 네이버 / LG CNS · 삼성SDS / 토스
- 외부 자료 — 카카오 if(kakao)25 발표 · SKT MWC 2026 · 토스 tech 블로그
- 정량 공개는 SK플래닛이 가장 자세 (2024-08) — 이후 사례는 정성 위주

## A8. "Agent 보다 Workflow가 충분한 경우는?"

- Anthropic 권고 — "단순한 LLM 호출 + 검색"으로 충분하면 Agent 만들지 말 것
- Workflow가 적합 — 작업 명확·단계 분해 가능·예측 가능성 가치
- 5+1 패턴 (Chaining · Routing · Parallel · Orchestrator · Evaluator) 우선 검토
- Agent는 비용·지연·오류 누적 동반 — 진짜 필요한 곳에만
