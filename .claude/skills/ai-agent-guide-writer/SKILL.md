# AI Agent Guide Writer — 산문형 강의 자료 저자

## 언제 호출되나
- lecture-orchestrator Step 4-A
- 사용자가 "가이드 작성", "핸드아웃", "강의 끝나고 줄 자료" 발화
- 입력 의존: `lecture/01-curriculum.md` + `lecture/02-architecture-canvas.md`

## 가이드의 역할
- 슬라이드는 강의 중 보는 것 → 정보 밀도 낮음
- 가이드는 강의 후 혼자 읽는 것 → **누락된 맥락을 산문으로 보완**
- 동일 다이어그램은 슬라이드와 가이드에 **그대로** 등장 (canvas 파일 인용)

## 청중 가정 (반복)
- SW/Cloud 아키텍트
- "이 챕터를 다 읽으면 우리 회사 화이트보드에 ___을 그릴 수 있다"가 각 챕터의 마지막 문장

## 톤 옵션 (사용자 결정)
| 옵션 | 특징 | 분량 가이드 |
|---|---|---|
| **친절체** | "~예요", "~인 거죠"로 풀어서 설명, 비유 풍부 | 챕터당 2,000~3,000자 |
| **요약체** | 명사구 위주, bullet 중심, 코드/표 비중 ↑ | 챕터당 800~1,500자 |
| **하이브리드** | 핵심 개념은 친절체, 표·체크리스트는 요약체 (default) | 챕터당 1,500~2,500자 |

## 챕터 템플릿 (모든 챕터에 동일 구조)

```markdown
## Ch{N}. {제목}

### 이 챕터에서 답할 질문
- (3~5개 질문)

### {핵심 개념} — 정의와 비유
{산문 1~3 문단. SW/Cloud 비유로 진입 → AI 고유 차이점 → 한 줄 정의}

### 캔버스: {C-id} (canvas 파일 §{id} 참조)
{ascii 다이어그램 그대로 인용}
**왜 이렇게 그렸나**: {한 문단}

### 의사결정 트리 — 언제 무엇을 쓰나
{표 또는 분기 리스트}

### 흔한 함정 / 안티패턴
- (3~5개)

### 이 챕터의 한 줄
> {수강생이 화이트보드에 그릴 수 있는 한 줄}

### 더 읽기 (선택)
- (1~3개 외부 링크 — trends-snapshot에서 가져옴)
```

## 산출 형식 (`lecture/03-guide.md`)

```markdown
# AI Agent 아키텍처 — 강의 가이드 (대상: SW/Cloud 아키텍트)
> 컷오프: 2026-05 / 작성일: YYYY-MM-DD
> 본 문서는 강의 후 자율 학습용. 슬라이드(`04-slides.html`)와 한 쌍.

## 어떻게 읽나
{1문단 — 강의 들으셨다면 챕터 순서대로, 처음 보시면 §1과 §6만 먼저}

## 학습 목표 (5)
{커리큘럼에서 가져옴}

## §1 ~ §6 챕터
{위 템플릿 6번 반복}

## 부록 A. 용어집
{Loop, Tool-call, Trajectory, MCP, A2A, ACP, Skill, Trace, Span, Checkpointer, Reflection, Critic 등 — SW/Cloud 비유와 함께}

## 부록 B. 의사결정 매트릭스 한 장
{Single vs Multi / ReAct vs Plan-and-Act / 자체구현 vs MCP / In-house vs Vendor — 한 장에 모음}

## 부록 C. 프로덕션 체크리스트
{Reliability / Eval / Cost / Security / Governance — canvas C12 인용}

## 부록 D. 추가 자료
{trends-snapshot의 출처 모음}
```

## 작성 룰
1. **모든 다이어그램은 canvas 파일 인용** — 가이드에서 새로 그리지 말 것 (`<!-- canvas:C1 -->` 마커 박기)
2. **새 사실 도입 금지** — canvas에 없는 표·결정 기준이 등장하면 architect skill로 돌려보내 canvas부터 갱신
3. **코드 분량은 전체의 15% 이내** — 청중은 아키텍트, 의사결정이 핵심
4. **출처 표기 강제** — 외부 사실(벤치마크, 사고 사례, 표준 버전)은 링크 필수
5. **각 챕터 끝에 "한 줄"** — 강의 학습 목표 검증용
6. **친절체 사용 시에도 단어 통일** — "에이전트"/"Agent" 중 하나로 고정 (default: Agent)

## 절차
1. `01-curriculum.md`, `02-architecture-canvas.md` 읽기
2. 사용자에게 톤 옵션 + 코드 분량 + 부록 범위 컨펌
3. 챕터 1개 먼저 작성 → 사용자 검토 → OK 받으면 나머지 5개 일괄
4. 부록 A·B·C·D 작성
5. 가이드 ↔ canvas의 다이어그램 정합성 자체 점검 (canvas ID 누락 검색)

## 절대 하지 말 것
- 슬라이드와 다른 표현으로 같은 개념 설명 (혼란 유발)
- canvas에 없는 의사결정 트리 즉흥 추가
- 회사 실명·사건을 추측으로 적기 — 출처 없는 사례 금지
- 기존 `slides/section-3-guide-*.md` 같은 파일 내용 차용 (사용자가 새로 작성 요청)
