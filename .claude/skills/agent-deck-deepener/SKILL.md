# Agent Deck Deepener — 슬라이드 깊이 보강

## 언제 호출되나
- 슬라이드의 한 카드/한 표 항목이 **이름과 한 줄 설명**으로만 구성되어 있을 때
- 사용자가 "그래서 어떻게 적용하나", "활용 방식이 안 보인다"고 지적할 때

## 한 항목당 갖춰야 할 6가지 (스니펫 표준)
모든 분류 항목(원칙·요소·패턴·도구·트렌드)은 다음 6필드로 채워져야 한다. 슬라이드 형식에 따라 표·카드·산문 어디든 다 들어가야 한다.

| 필드 | 내용 | 예 (P1 자율성·통제) |
|---|---|---|
| **정의** | 1~2문장. 무엇인가 | 에이전트의 자율 행위와 인간 검증 지점의 균형 |
| **적용 방식** | 어떤 산출물·매트릭스·코드로 구현되나 | HITL 진입점 매트릭스(Pre/Mid/Post × Approve/Edit/Reject) |
| **트레이드오프** | 무엇을 얻고 무엇을 잃는가 | 게이트 ↑ → 안전 ↑ 자동화 가치 ↓ |
| **적용 기준** | 어떤 조건에서 강도를 어떻게 조절하나 | 도구 위험도(LOW/MID/HIGH)별 진입점 수 결정 |
| **실패 신호** | 이 항목이 부재하면 어떤 사고가 나나 (가능하면 공개 사례) | Air Canada 챗봇 환불 약속 / Replit DB 삭제 |
| **체크포인트** | 아키텍트가 검증할 산출 질문 | 위험 거래 도구의 사전 승인자가 명시되어 있는가 |

## 우선순위 — 가장 빈약한 곳부터
1. **분류 인덱스 슬라이드** (n개 카드 나열): 각 카드에 6필드 압축본
2. **개별 디테일 슬라이드**: 6필드 모두 표·도식으로 펼침
3. **사례 슬라이드**: 위 6필드 중 "실패 신호"를 메인으로

## 표준 표 템플릿
```html
<table class="sk-table" style="font-size:clamp(0.72rem, 0.92vw, 0.85rem);">
    <thead>
        <tr>
            <th>{항목}</th>
            <th>정의</th>
            <th>적용 방식 / 산출물</th>
            <th>트레이드오프 / 적용 기준</th>
            <th>실패 신호 (부재 시)</th>
        </tr>
    </thead>
    <tbody>
        <tr>
            <td class="row-h"><strong>{이름}</strong></td>
            ...
        </tr>
    </tbody>
    <caption>{한 줄 정리}</caption>
</table>
```

## 절대 하지 말 것
- 카드에 이름 + 한 줄 설명만 두기 ("MCP — 도구 표준" 끝)
- 적용 방식 없이 트레이드오프만 나열
- 출처 없는 "권장 수치" (예: "X≥6에서 손익분기")
- 비유로 디테일을 대체 ("RPC 같은 거" 한 줄로 끝)

## 본 강의에서 깊이 보강을 권장하는 슬라이드
- 2.5 6원칙 인덱스 (이미 표로 보강 완료 v2)
- 3.0 Anthropic 패턴 카탈로그 — 패턴별 적용 시나리오·예제 추가 필요
- 3.2 도구 4요소 (이미 표로 보강 완료 v2)
- 4.1 추론 패턴 — 패턴별 입력·결과·비용·실패모드 표
- 5.1 HITL 진입점 — 진입점별 운영 디테일 (정보·SLA·감사)
- 5.4 공개 사례 (이미 표 보강)
- 7.1 운영 7체크 — 각 체크에 통과 기준·증빙 추가

## 사용 흐름
1. 대상 슬라이드 식별
2. 6필드 채우기 — 자료가 부족하면 WebFetch로 출처 검증
3. 표 또는 디테일 카드로 변환
4. agent-deck-reviewer로 검증
